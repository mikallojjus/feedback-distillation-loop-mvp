# Troubleshooting the walkthrough

`W` is `node agents/claim-tagger-mvp/scripts/walkthrough.mjs`.

| What happened | What to do |
|---|---|
| `W start` stopped halfway (exit 1) | Run `W start --resume <id>` once, with the id the report names. The script continues from its record and never creates a page or table twice; a lost create is checked by title before it is sent again. Do not start a second page. |
| `W start` says the page cannot be reached (exit 2) | Relay: "In Notion, open that page, choose the connections menu and add the claim tagger connection, or pick another page." Then wait for a link. |
| `W start` says the page is protected (exit 2) | The parent is a real table, one of its rows, the production page or one of its tables. Ask for another page. |
| A demo command says your Claude allowance ran out (exit 75) | Relay the report. When the allowance is back, the editor types the same command again; it continues where it stopped. |
| The promote report says PASS but the Agent edition of the press pool and AI Force claims in step 7 still names the old edition, and both still read Waits for you in Agent status | The run stopped before its last step. `W where` says so and points at `/claim-tagger demo follow-up`, which repeats the follow-up alone. |
| The promote report says FAIL | Relay it as printed: it names the claim and hands the editor the whole text to put into Editor wording (the rule as it was tested, with one added sentence). The editor edits or rejects in Lessons waiting and types `/claim-tagger demo promote` again. A second FAIL: the editor sets Status to Rejected; the demo ends there, and that is a correct outcome. |
| The editor decided a claim in Your queue and it is still listed there | Expected: Your queue lists the claims whose Agent status is Waits for you, and a decided claim keeps that status until the agent reads it again. On a practice page the follow-up of step 7 does that for the press pool and AI Force claims, so those two leave Your queue then; the USPS and Georgia claims were not part of the rule change, keep Waits for you and stay listed until the next tag run reads them again, and `W where` says the demo is complete all the same. `status` counts only the claims that are still to decide. Nothing is wrong, and the order of the three columns the editor fills in does not matter for the view. |
| `W verify` names a Claims view whose columns are out of order | The table's own view (or one of the three views) does not show the columns in the review order. Notion refused the change when the page was built (the build printed a line about it), or somebody moved a column. The engineer puts the columns back in the order of `page-design.md`; the page works without it. |
| A command says the agent is paused (exit 3) | The practice page's Agent settings row has Paused ticked, or `runs/PAUSED` exists in the demo folder. A person unticks it; then the same command again. |
| A command says the rulebook text was edited by hand (exit 4) | Someone changed When to use on the practice page's Rulebook. Relay the report; a person puts the text back (or the engineer runs the restore command for that demo); then the same command again. |
| The editor asks which page a command acted on | Every demo report names the practice page in its sentence. `W list` shows every practice page with its link and step, newest first, and marks the one the commands reach when no page is named ("used by the demo commands"). Without `--demo <id>` that is the newest finished practice page under the Demos sub-page whose profile the script can read; a page under Demo tests (the engineer's test runs) or a page of an older shape (the pages of 15 and 16 October show "unknown" in `W list`: their Claims table has the text column Agent tags and the older name of the verified tags) is never picked that way, only by naming it. |
| Two practice pages exist under Demos and the editor is on the older one | Tell the editor the commands act on the newest page under Demos and ask the engineer before continuing; do not delete or archive anything. A page under Demo tests never takes the editor's commands, however new it is. |
| A demo command says there is no practice page under Demos (exit 2) | Every page is under another parent, is not finished, or is of an older shape. Ask for a new page under the Demos sub-page, or name the page the engineer means with `--demo <id>` (`W list` shows the ids' pages). |
| `W where` says step 1 right after the editor typed `/claim-tagger demo status` | Expected: `status` writes nothing to Notion, so the page cannot show that step 1 was done, and it stays at step 1 until the tag step has run (typing `status` again does no harm). `W where` says step 2 only when a command that writes has filled Last run summary and the four claims still have no Agent status (for example a tag step that stopped early); the Next line is then `/claim-tagger demo tag`. At step 3 the Next line says "decide your four claims"; once some are decided it says "decide your remaining claims" ("your remaining claim" for the last one). |
| The editor typed `/claim-tagger demo distill` and the report says a decision has no note, and the Next line points at Needs your note | A decision that differs from the agent's tag and has no note is still read (from the claim and the rule alone) and flagged "without your note" in the claim's Agent reading; Needs your note lists those claims. The editor adds a line for the tag (a reason word first if known) and types `/claim-tagger demo distill` again; only that decision is read again. Nothing is wrong. |
| The report of `demo distill` says some decisions "could not be read this time" | A reading call failed twice, or its answer was refused (the refused answers are kept in the run's record). Nothing was written for those decisions; type `/claim-tagger demo distill` again, and only they are read. |
| `W verify` or `W list` shows a page as "unknown" and the engineer says it was made before 22 October | The page has the older shape: its manifest has a Why wrong column in the editor's work. It is reached only with `--demo <id>`; the editor gets a fresh page. |
