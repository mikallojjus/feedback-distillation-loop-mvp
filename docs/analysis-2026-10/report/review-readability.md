## How to apply this file

- Ids are stable: `P-` plain language, `V-` visuals, `G-` glossary, `C-` consistency, `R-` resolver. Line numbers (`L12`) refer to the part file as it is today; they shift after edits, so apply bottom-up or search for the quoted start words.
- In a rewrite, `[[x]]` means wrap that word in `<dfn data-t="x">...</dfn>` (and add the glossary entry if section 3 says it is missing). `{{count:key}}` placeholders are kept exactly as in the parts; never type a number that has a key.
- "Plain layer" = every `div.plain` summary plus every `div.sub` page without `data-layer="tech"`. "Technical layer" = the pages with it.
- Rewrites use the product owner's voice: "you" is the product owner, "the editor" is the editor (see P-60 for why).
- Suggested order of work: (1) truth first: R-01 to R-10 and C-01 to C-03, after the six decisions listed under section 4B ("Needs a decision before applying"); (2) glossary entries and marks (section 3), because the rewrites use `[[slug]]` marks; (3) the Plain rewrites (1B to 1E); (4) structure and visuals (section 2: split pages first, then cards, tables and figures); (5) `data/counts.json`: add a key, with a source, for every new number (the rank matrix, the weekly row estimate, the machine minutes, the decision count) and drop nothing that a part still uses; (6) `node build.mjs --strict` from the report folder, then open the page in Plain and in Technical at about 1,000 px and at 390 px.
- Build constraints that touch these fixes (README and `build.mjs`): every `dfn` needs a glossary `dt`, and every glossary `dt` needs at least one `dfn` somewhere (`build.mjs` L314 to L320), so the Technical-only entries in 3C each need one mark at their first use on a Technical page; a tab's first page must not be Technical; colours only from role tokens; no personal names (use roles); no `TODO` text; a numeric table cell is `td.num`; keep column headers short because header cells never wrap.
- After applying, these searches should return nothing in the parts: `pending your confirmation`, `queue.maxNewRows`, `resolver spike`, `Not yet verified end to end`, `tag group`, and the text "Decisions D1 to D16".

What this means for a reader who feels overloaded:

1. The Plain layer is three times the size of the Technical layer. A reader who stays in Plain meets 9,896 words, 32 tables (the Questions tab alone has 17), prompt sizes, cache reads, REST-client versions and file paths. "Plain" currently means "everything except the code-level pages".
2. The Questions tab has no Technical page at all, so every table in it (settings, prompt sizes, cost per call, other runs) is Plain.
3. The Summary does not answer the three questions the product owner asked (keep, cut, do next) in one place. "Keep" is never stated on the Summary; the verdict "The loop itself is sound" sits in the second page of the Summary, under a stat grid.
4. **The page is behind the repository.** `DECISIONS.md` now holds D17 to D24 (written while the report writer was running). They answer most of the "pending your confirmation" items, and D18 contradicts the recommendation printed in a dozen places (a cap of 50 new queue rows per run). The Geo source resolver is also verified. See C-01 to C-03 and R-01 to R-10. Fixing these first removes the biggest source of confusion: the page asks the product owner to decide things he has already decided.

Mechanics that limit what a fix can do (checked in `parts/script.js` and `parts/page.css`):

- The Plain/Technical switch hides only whole `div.sub` pages marked `data-layer="tech"` (script.js L117 to L126). The `div.plain` summary of a tab is always visible. `details.tech` folds are supported (script.js L116, page.css L65 to L73: closed in Plain, opened in Technical) but no part uses one yet, so they have never been rendered; check one visually before relying on them.
- A link from a Plain page to a Technical page switches the whole page to Technical without warning (script.js L146 and L165). Five such links exist: `03-features L53` and `04-debt L36` to `#debt-permissions`; `04-debt L51` to `#debt-docs`; `07-path L25` to `#versions-move`; `07-path L29` to `#versions-optimal`.
