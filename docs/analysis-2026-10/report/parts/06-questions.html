One claims table or many?

Short answer. One rulebook can serve several claims tables: the judge sees only the claim text and the rules, so a claim is judged once and its answer shared. The code needs a list of tables instead of one: U.S. Politics first, World affairs later.

What happens at thousands of claims?

Short answer. After three fixes the code copes. The editor does not: the first full pass would put {{count:scale.firstPassRows}} rows in the queue. Decided: no cap; the queue is sorted by confidence, the editor filters in Notion, and tags go live one at a time.

The six drafting rules

  1. One lesson per tag per run, at most {{count:distill.maxLessonsPerRun}} per run, ranked by distinct supporting claims.
  2. Group by tag and cited rule; the rule the editor names in Your reasoning wins over the one the agent cited.
  3. One Opus call may return up to {{count:distill.patternsPerCall}} patterns, each with the rows it rests on; only those rows count as support.
  4. Over {{count:distill.maxGroupRows}} rows: newest first, rows with reasoning first, both outcomes shown; the rest next run.
  5. Counter-evidence: the same rule with the opposite outcome first.
  6. Keep the threshold of {{count:distill.minClaims}} distinct claims and the checks against duplicate lessons and copied claim text.
