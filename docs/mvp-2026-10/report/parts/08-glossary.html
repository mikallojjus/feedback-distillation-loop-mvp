Glossary

Every term marked with * in the report, in plain words. Each tab also lists the terms it uses at its foot.

canary
A claim with a known right answer that the agent must always get right: one of the rulebook's own example claims, or a counter-example on the other side of a tag pair. Canaries are checked on each tagging run and again when a rule change is tested. A failing canary means a rule, the model or the agent broke, so nothing goes live until it is understood.
follow-up
The re-check after a rule change goes live. The agent judges the lesson's claims again under the new rules and writes Fixed, Still wrong or Not re-run on each decided row they came from, so editors can see what their decision changed.
gate
The test a rule change must pass before it goes live. The agent judges the same claims under the old and the new rules and compares them: every canary and every saved regression case that passed before must still pass, no tag with enough labelled examples may get measurably worse, and the tag the lesson targets must improve. The result is PASS, HOLD or FAIL.
lesson
What editor decisions teach about a rule, written so that it holds for claims nobody has seen yet. The agent drafts a lesson in the Rule changes database when decisions on different claims point the same way. A lesson changes the rulebook only after the rule owner approves it and it passes the gate; it is never pasted into the agent's prompt.
PASS / HOLD / FAIL
The three verdicts of the gate, written on every result card. PASS: the change improved the tag it targets and broke nothing, so it can go live. HOLD: the evidence is too thin to tell whether it helped, so the rulebook stays as it is and the lesson waits for more labelled claims. FAIL: the change broke something that worked, so it is not adopted; the rulebook keeps its text and the lesson is marked Rolled back.
promote
To take an approved lesson through the gate and, if it passes, write its text into the rulebook and mark the lesson Live (the /claim-tagger promote command). On HOLD or FAIL nothing is written to the rulebook, and the result card says why. A promoted rule can be rolled back exactly, because the previous text and version are kept.
regression case
One claim, one tag and the answer an editor decided, kept as a permanent test. Before a rule change goes live the agent runs every case again; one that passed before and fails after is a regression, and it fails the gate.
rubric version
The version label of the rulebook the agent used, written like 2026-10-13.1 and shortened to R1, R2 in this report. Every rule change that goes live creates a new version, and every run, queue row and result card records the version it used, so any tag can be traced to the exact rules that produced it.
rulebook
The Notion database that holds the rules the agent tags by: one row per tag, with its description, numbered "When to use" rules and example claims. The agent reads it before each run and changes it only when an approved lesson passes the gate.
small sample
A label on every result card, because the trial has few labelled claims. The gate asks for at least 5 labelled examples of a tag instead of 30, so a PASS means no sign of harm on the claims tested, not proof that the rule is better everywhere.
Tag outcome
An editor's decision on one claim and one tag: Applies, Does not apply, Needs evidence or Ask another editor. It is the editor's own field. The agent never writes it, and a decided tag is never overwritten.
trust breaker
A check that stops the agent when an editor's work might have been touched. After every write the agent compares the editor-owned fields on the pages it changed with a snapshot taken before; any difference pauses the agent and shows the field with its before and after values. A person looks, then clears the pause.
Why wrong
The reason an editor gives when overruling the agent or deciding against the written rule: Agent slip, Rule unclear, Rule should change, No tag fits or Other. Each value sends the fix somewhere different: a test, a wording change, a rule change or a new tag. Every value except Agent slip asks for one sentence of reasoning.
