Decisions and next steps

In short

  • Fourteen decisions shaped the MVP: eleven while building it, from where the code lives to the extra runs that separate a real flip from noise, and three from the persona reviews. Each is one line below.
  • The MVP built the core of the research's proposed path and left out what needs editors' time or more data: the gold set, blind labels, tuned caps, source reading, a second editor's approval, and the per-tag judge.
  • Next, in order: close the review round (the queue and the cards were made clearer after round 1), build the per-tag judge and put LS-1 through the gate again, then grow the labelled data before moving to the real database.
  • The risks that matter: interference between tags (seen in the trial), tiny samples, a model or Claude Code update changing the answers, and renamed Notion columns.

Moving to the real Claims to review database

  1. Map the columns. The real queue's columns onto Tag decisions: the editor fields (Tag outcome, Why wrong, Your reasoning, Decided by, Decided at), the agent columns to add, the formulas for Effective outcome, Direction and Stage, and the rollups the connector needs instead of formulas through relations.
  2. Re-point the configuration. The real database becomes a configured data source in config.json; U.S. Politics and the taxonomy stay protected; pull.mjs checks every property name and type against the real schema, and the allowlist is checked against its select options.
  3. Identity. A new integration token, shared only with the pages the agent writes. The connector stays with people.
  4. The rulebook. Copy the Verified tags of the day into the Rulebook again, or decide that the taxonomy itself becomes the rulebook; either way the file stays the source of truth and Notion is checked against it.
  5. Order. A tag dry run, then a small tag run with read-back, then the editors' queue, then distill and the gate as in the trial; each step checked before the next.
