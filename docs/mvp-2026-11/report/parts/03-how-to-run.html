How to run

In short

You type {{count:commands.typed}} commands yourself: status, tag, distill and promote. The follow-up runs by itself after a PASS, and the engineer sets things up and fixes what breaks. Every command ends with the same short report in three parts, and a practice page lets you try all of it before you decide a real row.

Built and run. Every command below ran against the Notion copy, and the whole cycle ran {{count:calibration.pagesAll}} times on practice pages. Commands go into Claude Code, opened in the project folder.

The seven steps, on a fresh practice page

The practice page has its own small tables, so nothing real changes. Build one, then follow the steps written on the page itself; each step has the same four parts: Goal of the step, Existing status, Doing the work and Explaining the outputs.

  1. Open your practice page "Claim tagger practice · product owner, 22 Oct" under Demos; it was built for you after the 22 October revision was verified, and it is the page the demo commands reach. To make another one later, ask Claude Code for a practice page and paste the link of the Demos page: /claim-tagger-walkthrough with the link.
  2. Type /claim-tagger demo status (step 1 of the page).
  3. Type /claim-tagger demo tag (step 2): the agent reads the {{count:walkthrough.claims}} claims and fills its side of your {{count:walkthrough.openRows}} rows.
  4. In Notion, in Your queue on the Claims table, decide your {{count:walkthrough.openRows}} claims (step 3): tick the tag in Verified tags where it applies, write your note (one line per tag when several; if you already know the reason, start it with Agent slip., Rule unclear. or Rule should change.), set Review status to Reviewed. The page gives you the words as a checklist, and Claude repeats it after the report. A decided claim stays in Your queue until the agent's next run picks it up.
  5. Type /claim-tagger demo distill (step 4): the agent reads each of your decisions, writes what it made of each in the Agent reading column, and drafts a rule change from the ones that point at the rule; then approve the draft in Lessons waiting (step 5).
  6. Type /claim-tagger demo promote (step 6). On a PASS the follow-up runs by itself and step 7 shows your rows marked Fixed. On a FAIL the report hands you the whole text for Editor wording: paste it, then type the same command again.

At any point, "where am I in the claim tagger demo" tells you the step you are at and the one thing to do next.

What you type

You type each command in Claude Code. At this stage one person is both the editor and the rule owner. Each command on the practice page is the same command with demo in front, and acts on the newest practice page.

If a command stops because the agent is paused, untick Paused in Agent settings (or delete the pause file) and run it again. If it stops because your Claude allowance ran out, wait and run the same command again: it picks up where it stopped. If it says the rulebook text was edited by hand, put the text back as it was, or ask the engineer.

Who does what

  • The editor types status and tag, then decides the claims in Your queue, least sure first: Verified tags is the decision, Review status Reviewed closes the claim, a note says what you saw. The agent works out whether the rule or its own reading was at fault; start the note with the reason word to overrule it. After each report Claude adds a short checklist of what to do in Notion and the next command.
  • The rule owner approves or rewrites lessons in Lessons waiting, then types promote.
  • The engineer does the setup, the rollback and the repairs, and nothing else.
  • The machine runs the follow-up after a PASS, without anyone typing.

Every command ends with the same three parts

  1. One sentence about what ran and what came out.
  2. One small table of at most five rows and three columns. It is left out when there is nothing to count.
  3. One line that starts with "Next:" and names exactly one thing to do: a command, or a Notion link and the action.

Nothing else is added: no run records, no durations, no costs. When more rows wait than fit one sitting, the Next line says "start at the top of Your queue". A report that comes from the practice page starts with "Demo ·" and names the page.

1 · What ran. Demo · Promote: PASS, rule 3 now uses the new wording (edition 2026-10-21.2), and the follow-up marked both of your rows Fixed (practice page Claim tagger practice · calibration 7).

What the practice page holds

/claim-tagger-walkthrough builds a fresh practice page under a Notion page you name; without a link it asks one question: "Under which Notion page should the demo go? Paste a link." The page has its own small tables, so nothing real changes, and you can build a new one whenever you want to practise again.

The page tells a small story about the Context-dependent tag and its rule 3 on descriptive references: {{count:walkthrough.openRows}} claims wait for you, {{count:walkthrough.decidedRows}} earlier decisions stand, and {{count:walkthrough.canaries}} example claims guard the safety check. The agent calls the press pool claim Context-dependent and you say that everyone knows the press pool; it cannot decide the AI Force claim and you say that a capitalised name nobody knows still needs context; it tags the USPS ballot portal and you say it slipped, because USPS names which portal; it leaves Georgia's debate untagged and you agree. The agent reads the first two as a problem with rule 3, takes your word on the third and has nothing to read on the fourth; your two rule notes become one changed rule 3.
