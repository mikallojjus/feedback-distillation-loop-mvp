How to run

In short

You type {{count:commands.typed}} commands yourself: status, tag, distill and promote. The follow-up runs by itself after a PASS, and the engineer sets things up and fixes what breaks. Every command ends with the same short report in three parts, and a practice page lets you try all of it before you decide a real row.

Planned, not built yet. None of these commands exists at this stage. This tab shows what each one will do, and it is rewritten when the loop runs.

What you type

You type each command in Claude Code. At this stage one person is both the editor and the rule owner.

CommandWhat it doesThen
/claim-tagger statusShows what is waiting: rows in the queue, lessons waiting, whether the agent is paused and the current rulebook edition.Open Your queue, or you are done.
/claim-tagger tagReads the claims against the rulebook, writes its tags and notes into two columns of the claims table, and puts every answer it is unsure about in the queue, least sure first.Decide the rows in Your queue.
/claim-tagger distillTurns decisions that blame a rule into proposed rule changes, called lessons, at most {{count:distill.maxLessons}} per run.Approve or rewrite each lesson in Lessons waiting.
/claim-tagger promote <lesson>Runs the safety check on an approved lesson. On a PASS the new rule goes live and a new edition starts. On a FAIL nothing changes and one sentence is proposed for Editor wording.After a PASS the follow-up runs by itself.

If a command stops because the agent is paused, untick Paused in Agent settings and run it again. If it stops because the usage limit is reached, wait and run the same command again: it picks up where it stopped.

Who does what

  • The editor types status and tag, then decides the rows in Your queue, least sure first.
  • The rule owner approves or rewrites lessons in Lessons waiting, then types promote.
  • The engineer does the setup and the repairs, and nothing else.
  • The machine runs the follow-up after a PASS, without anyone typing.

Every command ends with the same three parts

  1. One sentence about what ran and what came out.
  2. One small table of at most five rows and three columns. It is left out when there is nothing to count.
  3. One line that starts with "Next:" and names exactly one thing to do: a command, or a Notion link and the action.

Nothing else is added. When more rows wait than fit one sitting, the Next line says "start at the top of Your queue". A report that comes from the practice page starts with "Demo ·".

Try it before you decide a real row

/claim-tagger-walkthrough builds a fresh practice page under a Notion page you name. It has its own small tables, so nothing real changes, and you can build a new one whenever you want to practise again.

The page tells a small story about the Context-dependent tag: {{count:walkthrough.openRows}} rows waiting for you, {{count:walkthrough.decidedRows}} earlier decisions and the example claims that the safety check uses. You go through {{count:walkthrough.steps}} steps. Each step has the same four parts: Goal of the step, Existing status, Doing the work and Explaining the outputs.

StepWhat happensWhere
1You meet the practice page.In Claude Code
2The agent reads the claims.In Claude Code
3You decide your two rows, as the editor.In Notion, in Your queue
4The agent drafts a clearer rule from your decisions.In Claude Code
5You approve the draft, as the rule owner.In Notion, in Lessons waiting
6The safety check runs and, on a PASS, the new rule goes live.In Claude Code
7The agent re-checks your rows.Runs by itself

The last step has nothing to type. The page also explains why the two rows wait, how to fill in Why wrong, what each word means, and what to do when the agent is paused or the usage limit is reached.
